# 宝可梦对战树对手识别器 Battle Tree Recognizer (V3)

针对《宝可梦 究极之日 / 究极之月》**对战树**的对手配置识别工具。

通过 OCR 识别对手宝可梦的名字,自动从数据库匹配并打印其**道具、招式、性格、能力值与可能的特性**;同时支持单打、双打模式;支持预设关键配置(如气势披带、击掌奇袭、戏法空间)的**语音提示**。

---

## 功能特性

- 🎮 **手柄按键触发识别**(默认 ZL / ZR / 右摇杆按下 / Start),无需鼠标键盘
- 🔍 **高精度中文 OCR**(RapidOCR / PP-OCRv6),专门优化了**电气场地、妖精场地、白天等浅色背景**——浅色背景下普通 OCR 容易失败,本工具通过"黑色描边提取"通道依然稳定识别
- 📊 读取数据库 xlsx(15 列),打印:名字、**特性**、HP、攻、特攻、招式、道具、性格等
- 🔊 **语音提示**:在配置中预设需要警惕的道具 / 招式 / 特性,匹配到时自动播报(如"注意:雷丘,气势披带,击掌奇袭;智挥猩,戏法空间")
- ⚙️ **全配置化**:识别区域、遮罩、阈值、预处理通道、触发按键、数据库、提示项均可改配置,无需改代码、无需重新打包
- 🖥️ 无 GUI、纯命令行输出,轻量绿色
- 📦 独立打包(约 280MB),目标机无需安装 Python / 依赖

---

## 系统要求

- Windows 10/11(64 位)
- 一个游戏手柄(Joy-Con、Xbox 手柄等),用于按键触发
- 游戏画面(模拟器/采集卡)显示在主屏幕,识别区域为**全屏坐标**,可配置

---

## 快速开始

1. 解压本文件夹到任意位置(路径含中文亦可)
2. 双击 `启动.bat`
3. 等待命令行显示「数据库加载完成」与「OCR 引擎就绪」
4. 游戏中**对手出场时**,按下触发按键(默认 ZL / ZR / 右摇杆)
5. 命令行输出对手宝可梦配置表;若命中预设提示项,会语音播报

> 提示:识别一次后程序不会自动退出,可反复触发。

## 配置文件 `config.ini`

所有可调参数都在同目录的 `config.ini` 中,修改后**重启程序生效**。建议用记事本编辑并保持 UTF-8 编码。

```ini
[识别]
# 截图区域(游戏窗口全屏坐标,单位:像素)
x1 = 676
y1 = 64
x2 = 1560
y2 = 137
# 遮罩区域(相对截图区域的水平像素区间,此段置黑)
# 用于遮挡双打时中部的"状态(烧伤/麻痹等) / Lv50"文字,避免干扰 OCR
mask_x1 = 300
mask_x2 = 540
# OCR 前四周扩边(像素)
border = 60
# 高阈值:提取纯白文字(深色/浅色背景均适用)
high_thresh = 245
# 低阈值:提取黑色描边并反色(任意背景下都有效,浅色背景的关键)
low_thresh = 60
# 模糊匹配相似度阈值(0~1,越小越宽松)
match_cutoff = 0.4
# 使用的预处理通道,逗号分隔;只填一个=只用该通道;留空=全部
#   high    = 高阈值提取纯白文字
#   outline = 低阈值提取黑色描边并反色(推荐,浅色背景最稳)
#   clahe   = 灰度 CLAHE + 归一化
channels = high,outline,clahe

[触发]
# 触发识别的手柄按键编号,逗号分隔(支持中文逗号)
buttons = 4,6,7,9,10

[数据]
# 数据库文件名(与 config.ini 同目录,须为 .xlsx)
db_file = BattleTreeNpcPokemonStats_CN_New_Calc.xlsx

[提示]
# 语音提示开关(true/false)
tts_enabled = true
# 语速(Windows SAPI 范围 -10~10,0=正常,正值更快)
tts_rate = 0
# TTS 输出设备(留空=系统默认)。可填设备名片段做包含匹配,例如 "CABLE Input"
# 会把语音单独送到 VB-Audio Virtual Cable,供 OBS 采集,不影响其他应用声音。
tts_output_device =
# 需要提示的道具(逗号分隔,精确匹配)
alert_items = 气势披带
# 需要提示的招式(逗号分隔,精确匹配)
alert_moves = 击掌奇袭,戏法空间
# 需要提示的特性(逗号分隔,包含匹配;如"茂盛"会命中"茂盛／叶绿素")
alert_abilities =
```

**按键编号校准**:不同手柄/驱动的按键编号可能不同。若触发无效,可在识别前先临时把 config 里加一行 `debug` 或在触发时观察输出;更简单的方式是逐个试按,把生效的编号填入 `buttons`。

## 数据库说明

`BattleTreeNpcPokemonStats_CN_New_Calc.xlsx` 为对手配置数据库(15 列,共 996 行):


| 列   | 含义                                                   |
| ---- | ------------------------------------------------------ |
| 1    | 编号                                                   |
| 2    | 宝可梦名字                                             |
| 3    | 道具                                                   |
| 4-7  | 招式 1-4                                               |
| 8    | 性格                                                   |
| 9-14 | HP / 攻击 / 防御 / 特攻 / 特防 / 速度                  |
| 15   | **可能的特性**(多个特性用「／」分隔,如 `茂盛／叶绿素`) |

程序每次启动时重新读取该文件,**你可以自行维护更新数据库,替换文件后重启即生效**(无需重新打包)。

## 常见问题 (FAQ)

**Q:识别区域不对 / 识别不到名字?**
调整 `config.ini` 中 `[识别]` 段的 `x1/y1/x2/y2`,让裁剪区域正好框住屏幕上方的两个对手名字。不同分辨率/窗口位置需要重新校准。

**Q:双打时状态文字(烧伤/麻痹/Lv50)干扰识别?**
`mask_x1/mask_x2` 默认已把中部的状态与 Lv 文字置黑遮挡。若你的画面布局不同,微调这两个值。

**Q:语音没有声音?**

1. 确认 `tts_enabled = true`;
2. 确认系统安装了中文语音包(设置 → 时间和语言 → 语音,Windows 中文版自带 "Microsoft Huihui");
3. 若报 `⚠️ 语音播报失败`,可能是系统语音组件异常,重装语音包即可。

**Q:杀毒软件误报 / 报毒?**
PyInstaller 打包的程序可能被部分杀软误报,添加信任即可(本项目不联网、无任何后门行为)。

**Q:识别成功率还能更高吗?**
可以尝试:

- 浅色背景下优先用 `channels = outline`(描边通道对浅色背景最稳);
- 适当调低 `match_cutoff`(如 0.3)让模糊匹配更宽松;
- 保持截图区域干净,避免其他 UI 元素进入裁剪框。

## 技术实现(简介)

- **OCR 引擎**:RapidOCR(百度 PaddleOCR 的 PP-OCRv6 模型转为 ONNX,onnxruntime 推理),离线运行、模型内置。
- **预处理多通道策略**:同一截图生成 3 路预处理图像(高阈值白字 / 描边反色 / 灰度增强),分别 OCR,按「能否匹配到数据库宝可梦名 + 相似度」选最优结果。宝可梦游戏内文字自带**黑色描边**,浅色背景下白字与背景对比度低,但描边依然清晰——"描边反色"通道正是电场场景识别成功率高的关键。
- **约束匹配**:已知目标是固定宝可梦名列表,OCR 结果即使有少量错字,也能通过模糊匹配(编辑距离)纠正回正确名字,并自动过滤 "Lv50" 等无关文字。
- **语音**:直接调用 Windows SAPI(comtypes 同步播报),无需额外音频库。
